# A500 窗景产品方案 V2

> 主题：参照 iOS 全天候显示逻辑的三层待机状态重构  
> 版本：v2.0  
> 日期：2026-04-20  
> 适用范围：A500 窗景电视 / 息屏与陪伴场景

---

## 1. 方案重构背景

原方案中，窗景待机链路主要为：

`标准窗景 → MiniLED → AOD`

这套链路解决了“从完整内容到低功耗陪伴”的问题，但仍有两个不足：

1. **无人时仍可能亮屏**，无法真正解决“空间无人时的无效耗电”。
2. **状态边界不够清晰**，用户不容易理解为什么此时是完整窗景、为什么彼时是低功耗画面。

因此，本次重构参考 iOS 全天候显示的核心思路，不再单纯按“时间衰减”设计，而是改为：

> **基于“人在不在”与“有没有使用意图”两条判断线，构建三层待机状态。**

新的三层状态定义为：

```text
黑屏（No Presence）
  ↕
息屏显示（Low Power Ambient）
  ↕
屏保（Full Window Scene）
```

---

## 2. 新方案核心定义

### 2.1 三层状态重新定义

| 状态 | 定义 | 核心判断 | 目标 |
|---|---|---|---|
| 黑屏 | 屏幕基本关闭，仅保留传感和系统待机能力 | 检测无人在场 | 最大化节能 |
| 息屏显示 | 超低功耗内容 + 极简信息组件 | 有人存在，但无明确操作意图 | 低打扰陪伴 |
| 屏保 | 完整窗景内容持续演绎 | 用户在场，且可能有观看意图 | 氛围沉浸与内容价值 |

### 2.2 新的产品判断逻辑

新方案不再只依据“多久没有操作”，而是综合两类信号：

#### A. 存在信号：是否有人

- 毫米波 / 红外 / 摄像头存在检测
- 近场有人 / 远场有人 / 持续无人
- 是否为短时离开还是长时离场

#### B. 意图信号：是否想看

- 遥控器按键
- 语音唤醒
- 触控 / 手机投控
- 用户接近电视并停留
- 从系统主页进入窗景

一句话总结：

> **“有没有人”决定黑不黑屏，“有没有观看意图”决定是息屏显示还是完整屏保。**

## 3. 新的状态模型

## 3.1 状态关系图

```text
【黑屏】
  条件：无人 / 长时离场 / 夜间深度省电
  ↓ 检测到有人回到空间

【息屏显示】
  条件：有人存在，但未表达明确观看意图
  ↓ 用户靠近停留 / 按键 / 语音 / 主动进入
  ↑ 用户离远但仍在场

【屏保】
  条件：用户在场且有观看意图，或刚从内容场景退出
  ↓ 长时无操作 / 用户距离变远 / 注意力下降

【息屏显示】
  ↓ 持续无人

【黑屏】
```

## 3.2 三层状态的产品角色

### 黑屏

- 是“**无人状态**”
- 重点解决能耗、寿命与无意义亮屏
- 不强调内容表达

### 息屏显示

- 是“**有人但不打扰状态**”
- 重点提供时间感、空间陪伴感、夜间低存在感
- 是新的核心日常状态

### 屏保

- 是“**空间内容展示状态**”
- 重点提供完整窗景的沉浸、氛围、故事和品牌价值
- 是新的高价值内容状态

---

## 4. 新方案的设计原则

### 4.1 先判断“人在不在”，再判断“看不看”

黑屏不是待机的最末级附属状态，而是三层中的基础状态。  
如果空间里没人，电视不应继续扮演“窗”的角色。

### 4.2 让息屏显示成为默认陪伴层

真正高频使用的不是完整屏保，而是“有人在空间里，但并未直视电视”的状态。  
因此，息屏显示应成为 A500 最重要的日常陪伴层。

### 4.3 完整屏保只在用户“可能愿意看”时出现

完整窗景更美、更有故事，但也更耗电、更抢注意力。  
它不应全天常驻，而应在用户在场且存在观看意图时启动。

### 4.4 三层必须是同一个世界

黑屏、息屏显示、屏保不是三套 UI，而是同一个窗景世界的三种能级：

- 黑屏：世界休眠
- 息屏显示：世界微醒
- 屏保：世界展开

## 5. 重构后的完整用户旅程

### 5.1 家庭日常旅程

```text
无人时
  → 黑屏

用户进入客厅
  → 检测到存在
  → 息屏显示亮起（时间 + 微光窗景）

用户走近 / 坐下 / 看向电视 / 操作遥控器
  → 进入屏保
  → 展示完整窗景

用户继续停留但不操作
  → 屏保降级为息屏显示

用户离开客厅
  → 持续无人
  → 回到黑屏
```

### 5.2 夜间场景旅程

```text
卧室/客厅夜间
  → 有人但低活动
  → 默认息屏显示

若用户短暂查看时间/天气
  → 维持息屏显示

若用户明确想看窗景
  → 扩展到屏保

若用户离开/入睡
  → 转入黑屏
```

### 5.3 方案价值

这种设计带来三个直接收益：

- **更像 iOS 全天候显示**：人不在就黑，人回来就轻亮。
- **更符合家庭空间真实节奏**：不是永远展示完整内容。
- **更容易理解**：用户会自然接受电视“像有生命一样感知空间”。

## 6. 三层状态详细设计

## 6.1 状态一：黑屏

### 6.1.1 定位

黑屏是 A500 的“**无人态**”与“**极致省电态**”。

它不是传统意义上的完全关机，而是：

- 关闭主显示内容
- 保留低功耗传感器监听
- 保留必要系统时钟和唤醒服务

### 6.1.2 进入条件

满足任一条件即可进入：

- 持续检测 **无人 3~10 分钟**
- 夜间低活跃时段，且无人存在
- 用户主动选择“离场黑屏”
- 节能优先模式下的长时无交互

### 6.1.3 退出条件

- 检测到有人进入空间
- 语音唤醒
- 遥控器按键
- 手机投控呼起

### 6.1.4 体验设计

- 屏幕完全黑
- 不显示时间与信息
- 不播放音频
- 传感器进入低采样省电模式

### 6.1.5 产品价值

- 从根本上降低待机能耗焦虑
- 避免空房间里电视持续发光带来的“设备感”
- 强化“电视懂空间”的高级认知

---

## 6.2 状态二：息屏显示

### 6.2.1 定位

息屏显示是 A500 的“**人在场陪伴态**”。

它类似 iPhone 的全天候显示，但在电视场景下不是简单的黑底时钟，而是：

> **极低功耗的微光窗景 + 必要信息组件。**

### 6.2.2 核心目标

- 表达“空间里有人，我轻轻亮着”
- 让用户随时看见时间、天气、基础状态
- 保留窗景的气质，但不打扰空间

### 6.2.3 进入条件

满足任一条件可进入：

- 黑屏状态下检测到有人进入空间
- 屏保状态长时无操作降级
- 用户离电视稍远，但仍在客厅停留
- 夜间模式下系统默认使用息屏显示而非直接屏保

### 6.2.4 退出条件

- 用户主动操作或明确接近，升级到屏保
- 长时间无人存在，降级到黑屏

### 6.2.5 显示内容

#### A. 视觉内容

- 超低亮度微光窗景
- 保留主场景轮廓、光点、时间感
- 降帧率、降细节、降色彩饱和度

#### B. 信息组件

- 时间
- 天气
- 温度
- 睡眠/静音/白噪音状态
- 可选倒计时信息（如距日落、睡眠开始时间）

### 6.2.6 UI 设计原则

- 信息组件弱存在感
- 组件与窗景共融，而非浮于画面之上
- 在 3 米距离可读，但不抢主视觉

### 6.2.7 推荐显示规格

| 项目 | 建议值 |
|---|---|
| 亮度 | 5~15 nit |
| 帧率 | 1~5 fps |
| 色温 | 2400K~3200K |
| 内容形式 | 微光写实 / 剪影 / 光点 |
| 音频 | 默认关闭或极弱环境尾韵 |

### 6.2.8 体验关键词

- 安静
- 克制
- 有呼吸感
- 有人在时才亮

---

## 6.3 状态三：屏保

### 6.3.1 定位

屏保是 A500 的“**完整内容展示态**”。

这里的“屏保”不是传统系统屏保，而是完整的窗景内容层，承担：

- 真窗感
- 情绪氛围
- 轻叙事
- 品牌差异化展示

### 6.3.2 进入条件

- 用户从息屏显示状态主动操作
- 用户靠近并停留
- 用户进入客厅后直接按键/语音唤起
- 从主页进入窗景

### 6.3.3 退出条件

- 长时间无操作，降级为息屏显示
- 持续无人，进一步降级为黑屏
- 用户切换到其他业务内容

### 6.3.4 展示内容

- 完整窗景内容
- 时间/天气/季节同步
- 动态元素与故事调度
- 每日一诗 / 仪式化开场
- 环境音与近远场声效

### 6.3.5 推荐显示规格

| 项目 | 建议值 |
|---|---|
| 亮度 | 跟随环境光自动调节 |
| 帧率 | 12~30 fps（屏保态），关键动画可更高 |
| 音频 | 默认轻音量，可配置 |
| UI | 5 秒后自动隐去 |

### 6.3.6 体验关键词

- 沉浸
- 真实
- 有故事
- 值得被看

## 7. 新的状态切换规则

## 7.1 触发逻辑总表

| 当前状态 | 触发信号 | 下一状态 |
|---|---|---|
| 黑屏 | 检测到有人 | 息屏显示 |
| 黑屏 | 遥控器/语音/主动唤醒 | 屏保 |
| 息屏显示 | 用户靠近停留 / 按键 / 语音 | 屏保 |
| 息屏显示 | 持续无人 | 黑屏 |
| 屏保 | 长时无操作但仍有人 | 息屏显示 |
| 屏保 | 持续无人 | 黑屏 |

## 7.2 推荐时间阈值

| 项目 | 推荐默认值 |
|---|---|
| 屏保降级到息屏显示 | 3 分钟 |
| 息屏显示降级到黑屏 | 无人持续 5 分钟 |
| 黑屏唤醒到息屏显示 | 检测到人后 300~800ms |
| 息屏显示升级到屏保 | 操作后即时 / 接近后 1s 内 |

## 7.3 核心判断策略

### 方案建议：时间 + 传感器双因子

不建议只依赖时间，也不建议只依赖传感器。  
建议采用双因子综合判断：

```text
状态切换 = 无操作时长 + 人体存在置信度 + 用户距离 + 时段策略
```

示例：

- **人在但远**：保留息屏显示
- **人在且近**：进入屏保
- **无人**：进入黑屏

## 8. 三层状态下的内容策略重构

## 8.1 内容分层原则

原先内容按“完整窗景 / MiniLED / AOD”设计。  
现在应重构为“同一内容世界的三层表达”：

| 状态 | 内容表达层级 |
|---|---|
| 黑屏 | 无内容，仅保留系统感知 |
| 息屏显示 | 提炼后的内容符号 |
| 屏保 | 完整内容演绎 |

## 8.2 同一场景的三层表达示例

以“西湖夜景”为例：

### 黑屏

- 无画面
- 仅系统待机

### 息屏显示

- 仅保留湖面月光反射
- 远山轮廓弱可见
- 底部显示时间、天气

### 屏保

- 完整西湖夜景
- 月光、云层、水波、船影
- 虫鸣、远钟、环境氛围
- 轻故事调度

## 8.3 对内容制作的要求变化

原本内容制作关注“完整内容 + 低功耗版本”。  
现在需要明确一套“三态母版”：

1. **屏保母版**：完整内容版
2. **息屏提炼版**：轮廓 / 光点 / 微动版
3. **黑屏逻辑版**：仅状态管理，无内容资源压力

这意味着内容资产在立项时就要按三层交付。

## 9. 两大模块重新定义

## 9.1 息屏显示模块的新角色

在旧方案里，息屏显示更像最末级省电状态。  
在新方案里，它不再只是“快关机前的一层”，而是：

> **A500 最重要的高频陪伴层。**

其产品意义被抬高为：

- 有人时的默认空间反馈
- 夜间状态的主入口
- 黑屏与屏保之间的核心桥梁

## 9.2 空间场景模块的新角色

空间场景模块不再默认长时驻留，而是：

> **在用户在场且愿意看时，完整展开的内容世界。**

这意味着空间场景要更珍惜用户注意力：

- 开场更有仪式感
- 前 90 秒更有钩子
- 内容节奏更适合“被看见”

## 10. 功能架构调整建议

## 10.1 一级产品能力

| 一级能力 | 说明 |
|---|---|
| 存在感知引擎 | 判断人在不在、远近、停留状态 |
| 三层状态引擎 | 黑屏 / 息屏显示 / 屏保状态机 |
| 内容分层引擎 | 同一场景在三层状态下的差异化表达 |
| 信息组件系统 | 时间、天气、状态类组件 |
| 节能策略引擎 | 功耗、亮度、帧率、背光联动 |

## 10.2 系统状态机

建议状态机从“时间衰减型”改为“空间感知型”：

```text
输入：
- 用户操作
- 人体存在
- 用户距离
- 时间段
- 环境光

输出：
- 黑屏
- 息屏显示
- 屏保
```

## 10.3 设置项重构

建议将原设置重构为以下几类：

### A. 无人黑屏设置

- 无人后多久进入黑屏
- 是否允许夜间直接黑屏

### B. 息屏显示设置

- 是否开启息屏显示
- 信息组件类型
- 最大亮度
- 夜间暖色偏移

### C. 屏保设置

- 自动进入屏保时间
- 是否启用每日一诗
- 音频强度

### D. 感知设置

- 唤醒灵敏度
- 距离阈值
- 误触发保护

## 11. 关键交互细节

## 11.1 黑屏 → 息屏显示

目标：让电视像“感知到你回来了”。

建议表现：

- 0.3~0.8 秒内柔和点亮
- 先出现微光背景，再出现时间信息
- 不出现明显 UI 跳变

## 11.2 息屏显示 → 屏保

目标：让世界“展开”。

建议表现：

- 亮度平滑提升
- 轮廓补全为完整景观
- 动态元素逐步增加
- 若有音频，缓慢淡入

## 11.3 屏保 → 息屏显示

目标：让世界“收起”，不是被切断。

建议表现：

- 先降低动态频率
- 再淡化细节层
- 最后保留主轮廓和信息组件

## 11.4 息屏显示 → 黑屏

目标：像呼吸停止一样自然。

建议表现：

- 信息组件先淡出
- 场景微光后熄灭
- 全程不超过 1.5s

## 12. 新方案的指标体系

## 12.1 核心体验指标

| 指标 | 目标 |
|---|---|
| 黑屏误唤醒率 | 低 |
| 息屏显示驻留时长 | 高于完整屏保 |
| 息屏显示到屏保的转化率 | 可观测 |
| 用户对“懂我在不在”的感知 | 明显 |
| 夜间打扰投诉率 | 低 |

## 12.2 能耗指标

| 状态 | 目标 |
|---|---|
| 黑屏 | 接近深待机 |
| 息屏显示 | 极低功耗，显著低于屏保 |
| 屏保 | 可接受中低功耗，明显低于影音播放 |

## 12.3 内容指标

| 指标 | 目标 |
|---|---|
| 屏保 90 秒停留率 | 提升 |
| 每日一诗有效感知率 | 提升 |
| 内容重复感投诉率 | 降低 |

## 13. 重构后的产品结论

此次重构后，A500 不再是“一个一直在亮着的窗景电视”，而是一个：

> **会根据空间中有没有人、用户有没有观看意图，自动选择最合适存在方式的智能窗。**

三层状态各自承担不同使命：

- **黑屏**：解决无人时的无效能耗
- **息屏显示**：解决有人在场时的低打扰陪伴
- **屏保**：解决用户愿意看时的完整内容价值

这使 A500 的产品逻辑更接近用户真实生活节奏，也更接近 iOS 全天候显示背后的本质：

> **显示不是一直开着，而是根据人和场景，选择最合适的“存在程度”。**

---

## 14. 建议下一步

1. 以本方案为基础，重绘三层状态机与交互流  
2. 将原 `MiniLED` 重新定义为“屏保降级中的视觉过渡技术”，不再作为独立用户状态  
3. 按三层状态重新拆解视觉稿、内容稿、传感策略和研发接口  
4. 优先做一个 `黑屏 → 息屏显示 → 屏保` 的动态样板验证真实体验
