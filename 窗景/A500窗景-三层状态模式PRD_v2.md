## 一、设计变更说明

### 1.1 为什么要重新设计？

**原方案问题**：
- 过度依赖毫米波传感器进行人体检测
- 传感器方案存在成本、隐私、可靠性等问题
- 状态间的层级和关联关系不够清晰
- 用户对状态的感知和控制不够直观

**新方案目标**：
- 去掉毫米波传感器依赖
- 用直观的开关层级控制状态
- 理清状态的层级关系（谁依赖谁）
- 理清状态的关联逻辑（开关变化时如何联动）

### 1.2 核心设计理念

> **开关层级控制**：像控制灯光一样控制窗景状态
> - 总开关：控制整个窗景应用
> - 层开关：控制每一层的开启/关闭
> - 定时开关：控制自动进入/退出的时间
> - 关联开关：控制状态间的联动逻辑

### 2.2 开关类型定义

| 开关类型 | 作用 | 层级归属 | 说明 |
|---------|------|---------|------|
| **总开关** | 启用/禁用该层功能 | 每层独立 | 关闭后该层完全不可用 |
| **定时开关** | 设置自动进入该层的时间 | 每层可选 | 依赖上层开启 |
| **关联开关** | 控制是否响应上层/下层的联动 | 每层可选 | 控制状态跳转逻辑 |
| **手动开关** | 立即切换到该层 | 每层独立 | 用户主动触发 |
| **依赖检查** | 验证上层依赖是否满足 | 系统自动 | 不满足时不允许开启 |

## 三、状态层级与关联关系

### 3.1 状态层级定义

#### 3.1.1 层级划分

| 层级 | 状态 | 功耗 | 帧率 | 亮度 | 层级性质 |
|------|------|------|------|------|---------|
| **Level 0** | 黑屏（Dark） | ≈ 0W | 0fps | 0% | 基础层 · 可独立控制 |
| **Level 1** | 息屏显示（AOD） | < 5W | 1-5fps | 3%-12% | 中间层 · 依赖基础层 |
| **Level 2** | 屏保（Screen Saver） | 20-40W | 30-60fps | 20%-100% | 顶层 · 依赖中间层 |

#### 3.1.2 层级性质

```
┌─────────────────────────────────────────────────────────────┐
│                        层级性质说明                            │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  【基础层】Level 0 · 黑屏                                    │
│  ├── 性质：最底层，所有上层的基础                               │
│  ├── 独立性：可独立开启/关闭，不受上层影响                       │
│  ├── 依赖：无                                                 │
│  └── 关闭影响：关闭后所有上层自动关闭                           │
│                                                             │
│  【中间层】Level 1 · AOD                                     │
│  ├── 性质：连接底层和顶层的桥梁                                │
│  ├── 独立性：依赖基础层，可选开启                              │
│  ├── 依赖：需要黑屏开启才能开启                                │
│  ├── 关闭影响：关闭后顶层自动关闭，回归黑屏                      │
│  └── 开启时：可被手动/定时/关联触发进入                         │
│                                                             │
│  【顶层】Level 2 · 屏保                                      │
│  ├── 性质：最完整的体验层                                     │
│  ├── 独立性：依赖中间层，可选开启                              │
│  ├── 依赖：需要 AOD 开启才能开启                              │
│  ├── 关闭影响：关闭后回归 AOD 或黑屏                          │
│  └── 开启时：可被手动/定时/关联触发进入                         │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

### 3.2 状态关联矩阵

#### 3.2.1 开关状态组合矩阵

| 黑屏开关 | AOD开关 | 屏保开关 | 实际状态 | 说明 |
|---------|--------|---------|---------|------|
| **OFF** | 任意 | 任意 | 黑屏（强制） | 基础层关闭，全部回归黑屏 |
| **ON** | **OFF** | 任意 | 黑屏 | 基础层开启，中间层关闭 |
| **ON** | **ON** | **OFF** | AOD | 中间层开启，顶层关闭 |
| **ON** | **ON** | **ON** | 屏保 | 全部开启，最高层生效 |

#### 3.2.2 状态跳转关联

| 当前状态 | 开关操作 | 跳转目标 | 关联触发 |
|---------|---------|---------|---------|
| **黑屏** | 开启AOD | AOD | - |
| **黑屏** | 开启屏保 | AOD（先）→ 屏保 | 屏保依赖AOD |
| **AOD** | 开启屏保 | 屏保 | - |
| **AOD** | 关闭AOD | 黑屏 | 顶层随之中断 |
| **屏保** | 关闭屏保 | AOD | 退回中间层 |
| **屏保** | 关闭AOD | 黑屏 | 跳过中间层直接关闭 |
| **屏保** | 关闭黑屏 | 黑屏（强制） | 全部关闭 |

#### 3.2.3 定时触发关联

| 定时器 | 触发条件 | 跳转目标 | 前置检查 |
|-------|---------|---------|---------|
| **黑屏定时** | 无操作 T0 | 黑屏 | AOD/屏保先关闭 |
| **AOD定时** | 无操作 T1 | AOD | 黑屏必须开启 |
| **屏保定时** | 无操作 T2 | 屏保 | AOD/黑屏必须开启 |

### 8.2 依赖检查实现

```python
class SwitchDependency:
    """开关依赖检查器"""
    
    DEPENDENCIES = {
        'screen_saver': ['aod', 'dark'],      # 屏保依赖AOD和黑屏
        'aod': ['dark'],                        # AOD依赖黑屏
        'dark': []                              # 黑屏无依赖
    }
    
    def can_enable(self, target: str) -> tuple[bool, list[str]]:
        """检查是否能开启指定开关"""
        missing = []
        for dep in self.DEPENDENCIES[target]:
            if not self.is_enabled(dep):
                missing.append(dep)
        
        if missing:
            return False, missing
        return True, []
    
    def cascade_close(self, target: str):
        """级联关闭上层开关"""
        to_close = []
        for layer in ['screen_saver', 'aod', 'dark']:
            if layer == target:
                break
            if self.is_enabled(layer):
                to_close.append(layer)
        return to_close
```

### 8.3 定时器管理

```python
class TimerManager:
    """定时器管理器"""
    
    TIMERS = {
        'T0_dark': {'from': 'any', 'to': 'dark'},      # 无操作→黑屏
        'T1_aod': {'from': 'screen_saver', 'to': 'aod'}, # 屏保无操作→AOD
        'T2_saver': {'from': 'aod', 'to': 'screen_saver'}, # AOD无操作→屏保
    }
    
    def on_user_activity(self):
        """用户活动时重置所有定时器"""
        for timer in self.active_timers:
            timer.reset()
    
    def on_timeout(self, timer_id: str):
        """定时器超时时执行状态转换"""
        timer = self.TIMERS[timer_id]
        target_state = timer['to']
        
        # 检查前置依赖
        if self.check_dependencies(target_state):
            self.transition_to(target_state)
```

| 测试项 | 验收标准 |
|--------|---------|
| 开启屏保时自动开启AOD | AOD未开启时，开启屏保后AOD自动开启 |
| 开启AOD时自动开启黑屏 | 黑屏未开启时，开启AOD后黑屏自动开启 |
| 关闭黑屏时级联关闭AOD和屏保 | AOD和屏保跟随黑屏一起关闭 |
| 关闭AOD时关闭屏保 | 屏保跟随AOD一起关闭 |
| 定时触发正确执行 | 定时到达后正确进入对应状态 |
| 依赖检查阻止非法开启 | 无法开启不满足依赖的开关 |

### 10.2 状态转换验收

| 测试项 | 验收标准 |
|--------|---------|
| 状态指示器正确显示 | 当前状态和倒计时正确显示 |
| 遥控器快捷键正确响应 | 各按键执行正确的状态转换 |
| 语音指令正确响应 | 语音唤醒执行正确的状态转换 |
| 状态切换动画流畅 | 渐变动画无卡顿 |

## 附录：术语表（更新版）

| 术语 | 英文 | 说明 |
|------|------|------|
| 开关层级 | Switch Hierarchy | 三层状态的开关控制结构 |
| 总开关 | Master Switch | 控制该层功能启用/禁用的主开关 |
| 定时开关 | Timer Switch | 控制自动进入/退出的时间开关 |
| 关联开关 | Link Switch | 控制状态间联动逻辑的开关 |
| 依赖关系 | Dependency | 上层状态对下层状态的依赖 |
| 级联关闭 | Cascade Close | 关闭下层时自动关闭上层 |
| 上行联动 | Upward Link | 开启上层时自动开启下层依赖 |
| 下行联动 | Downward Link | 关闭下层时自动关闭上层 |
